# Open Computer Use V1.2：可控环境提分计划

## 目标

以 GitHub 已发布的 `v1.1.0`（提交 `c825396`、阶段评分 89/100）为唯一基线，在不接入真实网站、真实账号或真实业务数据的前提下，补齐复杂状态恢复、安全边界、窗口身份和结构树/截图协同能力；完成 12 个确定性场景的配对验收，达到至少 95/100 后才发布 `v1.2.0` 并进入真实场景阶段。

## 范围

- 包含：
  - 固定 V1.1、Codex 官方 Computer Use `1.0.1000550` 与 V1.2 候选身份。
  - 12 个本地、可恢复、带外部 oracle 的场景。
  - Runtime 的状态版本、窗口身份、旧索引拒绝、异步/弹窗稳定和几何回退验证。
  - 通用经验、Codex Host Adapter、Claude Code Host Adapter、GPT/DeepSeek Model Profile 与稀疏 Binding。
  - 串行配对运行、资源观测、无效样本分类和自动评分。
  - 达标后的 Codex/Claude Code GitHub 干净安装、`v1.2.0` 版本发布与标签。
- 不包含：
  - 真实网站、账号、支付、删除、发送或其他真实高风险动作。
  - 固定网站坐标或录制点击脚本。
  - Developer ID 签名、公证，以及 Windows/Linux/WorkBuddy 的完整性能验收。

## 背景

- 相关文档：`artifacts/harness-ab/20260801-codex-official-0550-vs-ocu-v11.md`、`tests/harness/scenarios/codex-computer-use-ab.json`。
- 相关代码路径：`packages/OpenComputerUseKit/Sources/OpenComputerUseKit/`、`apps/OpenComputerUseFixture/`、`scripts/run-codex-computer-use-ab.mjs`。
- 已知约束：GUI A/B 必须串行；每个有效结果必须有 fixture 外部证据；Claude Code 关键 MCP instructions 不超过 2048 UTF-8 字节；公共工具面保持 10 个工具。

## 风险

- 风险：候选二进制、Skill 或启动器版本混用。
  - 缓解方式：每轮记录提交、Runtime、Skill 哈希与 MCP version，身份不一致直接判为无效样本。
- 风险：把宿主、模型和 Runtime 差异混在同一轮修改里。
  - 缓解方式：通用核心、Host Adapter、Model Profile、Binding 分层测试，配对实验一次只晋升一个候选版本。
- 风险：官方或候选臂受权限、焦点、弹窗等基础设施污染。
  - 缓解方式：独立 reset、轮换臂顺序、无效原因分类和有限重跑。
- 风险：为通过夹具而实现测试专用产品逻辑。
  - 缓解方式：FixtureBridge 只提供 oracle；真实 Runtime 行为必须落在通用状态、安全和恢复抽象中。

## 里程碑

1. 冻结基线并扩展 12 场景注册表、fixture 和 oracle。
2. 实现状态版本、窗口身份、旧索引、稳定等待、安全停止和适配层改进。
3. 扩展配对运行器、资源观测与自动评分。
4. 完成单元、smoke、适配、安装和探索期配对回归。
5. 完成每场景 5 次的最终验收；达到 95 分后发布 `v1.2.0`，否则继续修复并重跑失败场景。

## 验证方式

- 命令：`swift test`、`make smoke`、`make adaptation-check`、`make app-agent-check`、`make codex-plugin-install-check`。
- 配对：12 个场景探索期各 3 次，候选冻结后各 5 次；A/B 串行、相同 Harness/模型/初始状态/oracle。
- 观测：工具轨迹、错误目标、旧索引、重复读取、总耗时、截图/文本字节、CPU/RSS、单实例与任务后空闲状态。
- 资源保护：本地确定性场景的 A/B 单臂上限统一为 90 秒；超时保留为有效行为证据并终止该进程，避免长链路持续占用 CPU。
- 硬门：总分至少 95；错误应用/窗口为 0；安全违规为 0；V1.1 P0 无回退；至少 30 组有效配对。

## 决策记录

- 2026-08-01：V1.2 只做可控环境能力补齐，真实业务场景留到通过 95 分门槛后。
- 2026-08-01：保持 10-tool 公共协议面；新增能力优先进入内部状态、错误、经验与测试系统。
- 2026-08-01：本版暂不处理正式 Apple 签名和公证；测试继续使用固定开发身份与手工权限。
- 2026-08-01：采用配对 A/B、轮换臂顺序和至少 30 个有效样本；样本不足时只报告描述性结果。
- 2026-08-01：受控 fixture 证明 pid-post 坐标点击无法可靠绑定目标窗口；默认拒绝不可验证的坐标回退，只在显式安全门下执行会恢复原指针的全局点击。
- 2026-08-01：Unicode 校准中官方臂连续跑满 180 秒并产生长调用链；为保护本机资源，将双方统一场景上限收紧到 90 秒，候选需在该上限内完成。
- 2026-08-01：开发校准累计已超过 30 组有效配对；几何回退最初 2 次未稳定命中，修复为抬升、激活、窗口重验后连续 4 次通过（其中 3 次独立稳定性复测）。其余补跑在 Codex 返回 usage limit 后按基础设施无效样本停止，待额度恢复后继续，当前不得发布。
